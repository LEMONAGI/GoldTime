# 1.2.0 요일별 규칙 — 실기기 검증 런북

기준일 D = 2026-07-11(토). 검증 완료 전 App Store 제출 금지(TODO.md).
판정은 전부 OSLog(`subsystem == "com.nagi.GoldTime"`)로 한다. 사람은 폰을 누르기만 하고,
"됐는지 아닌지"는 로그로 판정한다.

## 왜 이렇게 묶었나

TODO.md 항목 ①~⑧을 그대로 돌리면 자정을 4~5번 넘겨야 한다. 대신 **D일 밤에 요일 규칙을
7일치로 한 번에 설계**해두면, 이후 자정 3회(D→D+1, D+1→D+2, D+2→D+3)가 사람 개입 없이
서로 다른 전환을 밟는다. 사람이 폰을 만지는 건 4회(총 ~45분)뿐이다.

## 사전 조건

- **디버그 빌드**여야 한다(GTLog는 디버그 OSLog). Xcode에서 실기기로 Run.
- 그룹 4개 × 앱 1개씩. 자주 안 쓰는 앱으로 고른다(실사용 방해 최소화).
- 세션 0(업그레이드)을 하려면 **클린 재설치를 하면 안 된다** — 1.1.2 데이터 위에 덮어써야 한다.

## 요일 배치 설계 (세션 1에서 이대로 입력)

> **입력 제약(실측)**: 일일 한도는 **최소 0분·5분 단위**, 쿨다운 예산은 **최소 5분**.
> 1분 같은 값은 입력할 수 없다.

| 그룹 | 토(D, 오늘) | 일(D+1) | 월(D+2) | 화(D+3) | 검증 항목 |
|---|---|---|---|---|---|
| A `전환-쿨다운` | 일일 한도 **5분** | **쿨다운**(예산 5분/휴식 30분) | 제한 없음 | 일일 한도 5분 | ① |
| B `전환-해제` | 시간대 **23:00~23:59** | **제한 없음** | 제한 없음 | 일일 한도 5분 | ② |
| C `시간대-변경` | 시간대 **22:00~23:00** | 시간대 **07:00~09:00** | 제한 없음 | 일일 한도 5분 | ④ |
| D `시간대-동일` | 시간대 **21:00~21:30** | 시간대 **21:00~21:30**(동일) | 제한 없음 | 일일 한도 5분 | ④ 짝(무중단) |

A의 토요일은 **0분 → 제한 없음 → 5분** 순으로 세 번 저장해 ⑤(즉시 잠금 / 즉시 해제)를 함께
검증하고 5분으로 확정한다. 0분은 `used >= limit` 즉시 잠금 분기(모니터 미등록)를 탄다.

- 월(D+2)이 **전 그룹 '제한 없음'** → 하트비트 생존 검증(③).
- 화(D+3)에 daily 복귀 → 제한 없음 요일을 지난 뒤에도 재무장되는지(③ 후반).
- 수~금은 비워도 되고 '제한 없음'이어도 된다(검증 무관).

## 세션 0 — 1.1.x 업그레이드 (D일 아무 때나, ~15분) → 항목 ⑧

`SharedStore` Codable 하위 호환. 여기서 실패하면 **기존 사용자 그룹이 전부 소실**되므로 최우선.

```
Steps:
1. git worktree add ../GoldTime-112 1.1.2   (Mac에서 — 아래 명령 그대로 실행 가능)
2. Xcode로 1.1.2 워크트리를 열어 실기기에 Run (기존 앱 데이터 위에 설치)
3. 앱에서 그룹 2개 생성: 일일 한도 5분 / 시간대 차단 1개. 앱 1~2분 사용해 usedTime을 쌓는다
4. Xcode로 main(1.2.0) 빌드를 같은 기기에 Run — 삭제 없이 덮어쓰기
5. 앱 실행 후 홈 화면 확인
```

- **Expected result**: 3에서 만든 그룹 2개가 그대로 보인다. 이름·한도·시간대·오늘 사용량 유지.
  요일 토글은 OFF(기존 그룹은 weekdayRules nil). 기존 그룹의 잠금·해제가 1.1.2와 동일하게 동작.
- **Expected log trace**: `DailyLimit` `측정창 등록 group=… gen=…`이 기존 그룹에 대해 뜬다.
  그룹 목록이 비었으면 **즉시 실패**(배열 전체 `try?` 디코딩 → 1개 실패가 전체 소실).

## 세션 1 — 요일 세팅 + 광고 게이트 (D일 22:00~23:00, ~20분) → ⑤ ⑥ + UI 육안 일부

> 23:45 이후에 하지 말 것. 자정 직전엔 모니터 등록이 의도적으로 스킵돼(`intervalTooShort`
> 회피) 다음 자정의 "어제 등록 스냅샷" 전제가 흐려진다.

```
Steps:
1. 그룹 A~D를 만들고 각각 요일 규칙 토글 ON → 위 표대로 요일 묶음을 채운다
2. 각 그룹 저장(완료). 변경 완료 시 안내 카드 → 광고 → 보상 후 커밋되는지 본다
3. 저장 후 시트를 다시 열어 규칙이 그대로인지 확인(persist 왕복)
4. 적용된 그룹의 규칙 편집 시트를 그냥 열었다 닫는다(변경 없이)
5. 그룹 A의 오늘(토) 규칙을 일일 한도 1분으로 바꿔 완료 → 광고 → 즉시 잠금 경고 확인
6. 그룹 A의 앱을 1~2분 사용
```

- **Expected result**
  - 2: 규칙을 **바꾼 뒤 완료**할 때만 안내 카드("광고 보고 변경하기") → 실제 보상형 광고 → 보상 후 커밋·시트 닫힘.
  - 4: **광고·안내 없이** 열리고 닫힌다(보기 무료 — 1.2.0에서 게이트가 완료 시점으로 이동).
  - 5: 광고 뒤에 즉시 잠금 경고가 뜬다(광고 때문에 누락되지 않음).
  - 6: 1분 초과 시 그룹 A 앱이 Shield로 잠긴다.
- **Expected log trace**
  - `TimeWindow` `시간대 window 등록 group=… windows=N` (B·C·D)
  - `TimeWindow` `시간대 알림 예약 계획 N개 (iOS pending 64 제한)` → **N이 64 미만인지 확인**(⑥ 전반)
  - `DailyLimit` `측정창 등록 group=전환-쿨다운… limit=1m gen=…`
  - 6 이후 `Activity` `intervalDidStart`/threshold + `Shield` 계열 잠금 로그
- 23:00에 그룹 B가 시간대로 잠기는 것을 확인한다(**잠긴 채로 자정을 넘겨야 ②가 성립**).

## 세션 2 — 첫 자정 판정 (D+1(일) 아침, ~15분) → ① ② ④ ⑥ 후반

먼저 로그부터 수집한다(폰을 만지기 전에).

```
! sudo log collect --device --last 12h --output /tmp/goldtime-d1.logarchive
```
```
log show /tmp/goldtime-d1.logarchive --info --debug --predicate 'subsystem == "com.nagi.GoldTime"'
```

- **Expected log trace** (자정 00:00 전후, 순서대로)
  1. `Shield` `자정 리셋 + 재무장 시작` ← 이게 없으면 나머지는 볼 것도 없이 **실패**
  2. **①** `Cooldown` `재무장: 예산 측정 등록 전환-쿨다운… budget=1m gen=…`
  3. **②** `TimeWindow` `재무장: 요일 전환 오늘 비추적 → window 정리 전환-해제…`
  4. **④** `TimeWindow` `재무장: 요일 전환 window 재등록 시간대-변경… windows=1`
  5. **④ 짝** `TimeWindow` `재무장: 시간대 구성 동일 → 등록 기록만 복원 시간대-동일…`
- `재무장: … 실패`(error) 로그가 하나라도 있으면 실패로 판정한다.

로그 확인 후 폰에서:

```
Steps:
1. 그룹 B(오늘 제한 없음)의 앱을 연다 → 잠기지 않아야 한다 (②: 어제 잠긴 채 넘어왔음)
2. 그룹 A의 앱을 1~2분 사용 → 예산 1분 소진
3. 07:00~09:00 사이에 그룹 C의 앱을 연다 → 잠겨야 한다 (④)
```

- **Expected result**: 2에서 예산 소진 시 잠기고 "휴식 30분" 상태가 된다.
- **Expected log trace**: `Cooldown` cdtick 도착 → 예산 소진 잠금 로그, `Activity` tick 로그.
- ⑥: 시간대 알림이 **그날 규칙이 있는 그룹에만** 도착했는지 알림 센터로 확인
  (일요일에 B의 시간대 알림이 오면 실패 — 일요일 B는 제한 없음).
